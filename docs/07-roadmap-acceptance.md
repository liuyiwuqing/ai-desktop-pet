## 2. 关键依赖

```text
P0 ──► P1 ──► P2 ──► P3 ──► P4
              │       │
              └──► P5 ──► P6
P1 ──► P4（传感器联动）
P3 ──► P4（消息事件/成就）
P2 ──► P5/P6（意图）
```

- 不跳过 P1 直接做 P2：音频/屏幕未稳定时，AI 延迟与卡顿无法归因。
- 不跳过 P3 直接做 P5：没有消息/意图路由，设备控制缺少统一事件边界。
- P5/P6 可以并行，但都必须先完成契约与 mock。

## 4. 总体验收

### 功能

- 语音：唤醒率 ≥95%、误唤醒 ≤1 次/小时、首响 ≤1.5 s、可打断。
- 消息：Webhook 到上屏 ≤2 s、去重、离线队列、DND、critical 越过。
- 温湿度：5 s 更新、异常处理、60 分钟图表、故障自恢复。
- 成长：8 种状态、互动幂等、掉电存档、每日重置。
- 扩展：L0/L1 设备控制可用；L2 必须确认；舵机限位/急停有效。

### 资源与稳定性

- 内部 heap 最低 ≥80 KB；最大连续块 ≥32 KB；PSRAM ≥1 MB 空闲。
- UI 单帧 ≤16 ms；音频欠载可恢复；无 WDT。
- 24 h 连续运行无重启；7 天无存档损坏/内存下降。
- NVS 写入频率在预算内；OTA 可回滚。

### 安全

- 每设备独立凭据；MQTT 主题 ACL 隔离。
- 不执行任意 shell/路径/URL；设备控制白名单。
- 日志不含音频原文、令牌、Wi-Fi 密码、完整转写。
- DND/静音时麦克风关闭或门控，屏幕可见。

### 测试

- 主机：状态机、解析器、成长公式、CRC、schema、队列。
- 契约：MQTT 信封、Webhook 签名、Bridge 白名单、设备控制意图。
- HIL：屏幕、音频、传感器、断网、掉电、24 h/7 d。

## 5. 交付节奏

1. 先确认 `00-architecture.md` 与目录骨架。
2. 逐模块确认 `01`–`06`；每次只确认一个，记录修改。
3. P0 完成后生成 `firmware/main/CMakeLists.txt`、板级配置、分区表草案。
4. P1 开始写代码；每个切片先写失败反馈/主机测试，再做实机。
5. 每阶段结束更新本目录方案与本文件状态表。
