## 2. 核心数值体系

### 2.1 数值表

| 数值 | 范围 | 初始 | 作用 |
| --- | --- | --- | --- |
| `level` | 1–99 | 1 | 等级门槛与表现解锁 |
| `exp` | 0–`exp_to_next-1` | 0 | 升级进度 |
| `coins` | 0–999,999 | 20 | 互动/装扮消耗 |
| `intimacy` | 0–100 | 10 | 亲密度，影响对话语气与表现 |
| `mood` | -100–100 | 20 | 心情，影响表情 |
| `energy` | 0–100 | 80 | 精力，影响互动与睡眠 |
| `hunger` | 0–100 | 70 | 饥饿度，越低越饿 |
| `health` | 0–100 | 100 | 健康，长期照料结果 |

### 2.2 升级曲线

```text
exp_to_next(level) = 80 + 40 * (level - 1) + 8 * (level - 1)^2
```

| 等级 | 升下一级所需 EXP |
| --- | --- |
| 1 | 80 |
| 5 | 368 |
| 10 | 1,088 |
| 20 | 3,192 |
| 50 | 21,248 |
| 99 | 78,608 |

- 单次增加 EXP 后循环扣减，支持一次升多级；上限 99，溢出转为金币（可选）。
- 所有数值用整数存储；浮点只用于显示与曲线计算。
- 任何结算先做范围夹紧，再写存档；禁止负数/NaN。

### 2.3 时间衰减

| 数值 | 清醒 | 睡眠 | 说明 |
| --- | --- | --- | --- |
| `hunger` | -4 /h | -2 /h | 低于 20 触发饥饿 |
| `energy` | -3 /h | +8 /h | 低于 20 触发困倦 |
| `mood` | 向 0 回归 1/h | 不变 | 饥饿/低精力时 -1/h |
| `intimacy` | 无互动 24 h 后 -1/天 | 同左 | 最低 0 |
| `health` | 饥饿<10 或精力<10 持续 6 h：-2/h | 同左 | 全部 >50 时 +1/h |

离线结算上限 8 h；超过部分不累积，避免长期不开机导致“死亡”。时间使用单调时钟 + SNTP；检测到回拨不补奖励。

## 3. 互动与成长逻辑

| 互动 | 触发 | 数值变化 | 冷却/上限 |
| --- | --- | --- | --- |
| 喂食 | 按键/触摸/语音 | `hunger +30`、`exp +8`、`intimacy +2`、`coins -5` | 30 min；`hunger>90` 时 `mood -5` |
| 摸头 | 触摸/语音 | `intimacy +1`、`mood +3`、`exp +2` | 10 s；每日 20 次后收益减半 |
| 对话 | 每轮 AI 对话 | `exp +2`、`intimacy +1` | 每日 50 轮 |
| 玩耍 | 游戏入口 | `mood +10`、`exp +15`、`energy -10`、`coins +3` | 15 min；精力<20 拒绝 |
| 专注 | 25 min 计时完成 | `exp +20`、`coins +10` | 每日 8 次；需完成计时 |
| 睡觉 | 夜间/手动 | `energy` 恢复；`hunger` 衰减减半 | 睡眠中不结算玩耍 |
| 每日任务 | 3 个任务 | 每条 `exp +15`、`coins +5` | 每日 04:00 重置 |
| 成就 | 条件达成 | `coins`/装饰解锁 | 一次性 |

防刷规则：

- 同一互动按 `requestId` 幂等；重复事件不重复结算。
- 互动请求带时间戳；与服务器/单调时钟偏差 >5 min 拒绝。
- 对话收益按轮次计，流式 token 不重复计数。
- 专注完成以计时器真实结束为准，暂停/取消不发奖励。
- 单次结算原子化：先算新值，再写存档，成功后才发 UI 事件。

## 4. 状态推导与宠物表现

### 4.1 状态优先级

```text
SICK > HUNGRY > SLEEPY > SAD > FOCUS > EXCITED > HAPPY > IDLE
```

`SLEEPING` 为显式模式：除 `SICK` 外优先展示睡眠；唤醒后回到推导状态。`EXCITED` 为 3 s 瞬态，不持久化。

| 状态 | 条件 | 表情 | 动作 | 文案示例 |
| --- | --- | --- | --- | --- |
| `SICK` | `health < 30` | 皱眉、冷汗 | 蜷缩、慢呼吸 | “我有点不舒服……” |
| `HUNGRY` | `hunger < 20` | 眼巴巴、嘴张 | 看向食物图标、轻跳 | “肚子咕咕叫” |
| `SLEEPY` | `energy < 20` 或 22:00–07:00 | 半闭眼 | 点头、Zzz | “好困……” |
| `SAD` | `mood < -30` | 下垂眼、波浪嘴 | 低头、缓慢摇晃 | “陪我一会儿吧” |
| `FOCUS` | 专注计时中 | 认真、少眨眼 | 端坐、计时气泡 | “专注中 25:00” |
| `EXCITED` | 升级/成就 | 星星眼 | 上跳、转圈 | “升级啦！” |
| `HAPPY` | `mood > 50` 且主要数值 >50 | 笑眼 | 轻摆、招手 | “今天心情不错” |
| `IDLE` | 其他 | 微笑、眨眼 | 呼吸、张望 | 无 |

环境联动：温度 >30 °C 或 <10 °C、湿度 <30% 或 >80% 时，`mood` 每小时额外 -1，并播放对应冷/热/干/湿动作；不直接修改 `health`，避免传感器异常放大。

### 4.2 表现资源

- 每个状态至少 2 个循环动画 + 1 个进入动画；帧率 20–30 fps。
- 状态切换 100 ms 交叉淡入；`SICK`/`HUNGRY` 不允许被普通动作打断。
- 动作与 `01-ai-agent.md` 的 `motion_sink` 共用；后续舵机只替换执行层。

## 5. 存档与持久化

### 5.1 存档结构

```c
typedef struct {
    uint32_t magic;          // 'PETG'
    uint16_t version;        // 1
    uint16_t length;
    uint32_t sequence;
    uint32_t crc32;
    uint32_t saved_at_ms;
    // 数值
    uint8_t level;
    uint32_t exp;
    uint32_t coins;
    uint8_t intimacy, mood, energy, hunger, health;
    // 每日/成就
    uint16_t daily_talk_count;
    uint16_t daily_pet_count;
    uint8_t daily_focus_count;
    uint32_t daily_reset_day;
    uint32_t achievements_bitmap;
    uint16_t inventory_bitmap;
    // 预留
    uint8_t reserved[32];
} growth_save_v1_t;
```

- 存 NVS `pet_growth`，双槽 A/B；写非活动槽 → 读回校验 CRC → 更新活动槽指针。
- 写入时机：重要事件（升级/购买/任务完成）立即写；普通衰减每 5 min 合并写；掉电最多丢 5 min。
- 写入前检查 NVS 剩余空间；失败保留 RAM 状态并重试，不阻塞 UI。
- 读取：两槽都校验，选 `sequence` 更大且 CRC 正确者；都坏则使用默认值并备份原始 blob 到 LittleFS。
- 版本迁移：按 `version` 解码；未知版本不覆盖，提示用户导出备份。
- 工厂重置：管理台/长按组合键二次确认；只擦 `pet_growth`，不动网络凭据。
- 导出/导入：JSON（数值 + 时间 + 版本），通过 USB/HTTP；导入前校验范围与版本。

### 5.2 服务端同步（二期）

- 每 5 min 或重要事件上传 `growth_snapshot`，带 `deviceId`、`sequence`、`checksum`。
- 冲突：设备本地数值优先；服务端只校验奖励合法性并记录，不回写覆盖。
- 离线奖励/活动由服务端下发，设备幂等领取；首版不做。

## 7. 验收标准

### 功能

- 互动后 100 ms 内数值与 UI 更新；重复请求不重复结算。
- 升级曲线与表格一致；一次升多级正确；99 级封顶。
- 8 种状态按优先级展示，无卡死；状态切换 100 ms 内完成。
- 每日 04:00 重置任务与计数；跨时区/手动改时间不重复发奖。
- 离线 8 h 衰减符合公式；超过 8 h 不再累积。
- 掉电写入中重启：至少保留上一份有效存档；无 CRC 错误导致的无限重置。
- 导出/导入往返一致；未知版本拒绝覆盖。

### 资源与稳定性

- 存档写入 ≤50 ms；不阻塞 UI/音频。
- NVS 写入频率 ≤1 次/5 min（普通衰减）+ 重要事件；24 h 写入次数在预算内。
- 1000 次随机互动无溢出/NaN；数值始终在范围内。
- 30 天模拟衰减不出现负值/异常状态。

### 测试

- 主机：EXP、衰减、互动、状态机、CRC、迁移、幂等。
- 目标：NVS 双槽、掉电模拟、UI 动画。
- HIL：连续 7 天互动/断电/恢复。

## 8. 风险与待确认
