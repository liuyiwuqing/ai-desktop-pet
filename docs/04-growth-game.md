# 04 · 养成系游戏玩法模块

## 1. 范围

## 2. 核心数值体系

### 2.1 数值表

| 数值 | 范围 | 初始 | 作用 |
| --- | --- | --- | --- |
| `level` | 1–99 | 1 | 等级门槛与表现解锁 |
| `exp` | 0–`exp_to_next-1` | 0 | 升级进度 |
| `coins` | 0–999,999 | 20 | 互动/装扮消耗 |
| `intimacy` | 0–100 | 10 | 亲密度，影响对话语气与表现 |
| `mood` | -100–100 | 20 | 心情，影响表情 |
| `energy` | 0–100 | 80 | 精力，影响互动与睡眠 |
| `hunger` | 0–100 | 70 | 饥饿度，越低越饿 |
| `health` | 0–100 | 100 | 健康，长期照料结果 |

### 2.2 升级曲线

```text
exp_to_next(level) = 80 + 40 * (level - 1) + 8 * (level - 1)^2
```

| 等级 | 升下一级所需 EXP |
| --- | --- |
| 1 | 80 |
| 5 | 368 |
| 10 | 1,088 |
| 20 | 3,728 |
| 50 | 21,248 |
| 99 | 80,832（已封顶，不再升级） |

- EXP 达到门槛后升级；99 级封顶、EXP 清零，G1 不将溢出转金币。
- 属性使用整数定点数（1 点 = 3600 单位），按秒衰减，保留收益减半和睡眠切换的小数；显示时取整。
- 结算先校验与夹紧，再写存档；仅 `mood` 允许负数，范围 -100–100。

### 2.3 时间衰减

| 数值 | 清醒 | 睡眠 | 说明 |
| --- | --- | --- | --- |
| `hunger` | -4 /h | -2 /h | 低于 20 触发饥饿 |
| `energy` | -3 /h | +8 /h | 低于 20 触发困倦 |
| `mood` | 向 0 回归 1/h | 不变 | 饥饿/低精力时 -1/h |
| `intimacy` | 无互动 24 h 后 -1/天 | 同左 | 最低 0 |
| `health` | 饥饿<10 或精力<10 持续 6 h：-2/h | 同左 | `hunger`/`energy`/`mood` 均 >50 时 +1/h |

离线结算上限 8 h；超过部分不累积，避免长期不开机导致“死亡”。时间使用单调时钟 + SNTP；检测到回拨不补奖励。

## 3. 互动与成长逻辑

| 互动 | 触发 | 数值变化 | 冷却/上限 |
| --- | --- | --- | --- |
| 喂食 | 按键/触摸/语音 | `hunger +30`、`exp +8`、`intimacy +2`、`coins -5` | 30 min；`hunger>90` 时 `mood -5` |
| 摸头 | 触摸/语音 | `intimacy +1`、`mood +3`、`exp +2` | 10 s；每日 20 次后收益减半 |
| 对话 | 每轮 AI 对话 | `exp +2`、`intimacy +1` | 每日 50 轮 |
| 玩耍 | 游戏入口 | `mood +10`、`exp +15`、`energy -10`、`coins +3` | 15 min；精力<20 拒绝 |
| 专注 | 25 min 计时完成 | `exp +20`、`coins +10` | 每日 8 次；需完成计时 |
| 睡觉 | 夜间/手动 | `energy` 恢复；`hunger` 衰减减半 | 睡眠中不结算玩耍 |
| 每日任务 | 3 个任务 | 每条 `exp +15`、`coins +5` | 每日 04:00 重置 |
| 成就 | 条件达成 | `coins`/装饰解锁 | 一次性 |

防刷规则：

- 同一互动按 `requestId` 幂等；所有本地调用方从快照取 `next_request_id`，成功后递增，重试沿用原 ID。历史 ID 不再发奖；同 ID 与最近动作冲突、跳号或并发抢占返回 `CONFLICT`。
- G1 请求使用本次启动的单调毫秒时间，与当前时钟偏差 >5 min 拒绝；远端请求必须经后续适配层转换，不能直接传 Unix 时间。
- 对话收益按轮次计，流式 token 不重复计数。
- 专注完成以计时器真实结束为准，暂停/取消不发奖励。
- 单次结算原子化：先算新值，再写存档，成功后才发 UI 事件。

## 4. 状态推导与宠物表现

### 4.1 状态优先级

```text
SICK > HUNGRY > SLEEPY > SAD > FOCUS > EXCITED > HAPPY > IDLE
```

`SLEEPING` 为显式模式：除 `SICK` 外优先展示睡眠；唤醒后回到推导状态。`EXCITED` 为 3 s 瞬态，不持久化。

| 状态 | 条件 | 表情 | 动作 | 文案示例 |
| --- | --- | --- | --- | --- |
| `SICK` | `health < 30` | 皱眉、冷汗 | 蜷缩、慢呼吸 | “我有点不舒服……” |
| `HUNGRY` | `hunger < 20` | 眼巴巴、嘴张 | 看向食物图标、轻跳 | “肚子咕咕叫” |
| `SLEEPY` | `energy < 20` 或 22:00–07:00 | 半闭眼 | 点头、Zzz | “好困……” |
| `SAD` | `mood < -30` | 下垂眼、波浪嘴 | 低头、缓慢摇晃 | “陪我一会儿吧” |
| `FOCUS` | 专注计时中 | 认真、少眨眼 | 端坐、计时气泡 | “专注中 25:00” |
| `EXCITED` | 升级/成就 | 星星眼 | 上跳、转圈 | “升级啦！” |
| `HAPPY` | `mood > 50` 且主要数值 >50 | 笑眼 | 轻摆、招手 | “今天心情不错” |
| `IDLE` | 其他 | 微笑、眨眼 | 呼吸、张望 | 无 |

环境联动：温度 >30 °C 或 <10 °C、湿度 <30% 或 >80% 时，`mood` 每小时额外 -1，并播放对应冷/热/干/湿动作；不直接修改 `health`，避免传感器异常放大。

### 4.2 表现资源

以下为完整资源与联动目标；G4 首版采用原生图元和 100 ms 进入形变，具体实现与差异见第 12 节。

- 每个状态至少 2 个循环动画 + 1 个进入动画；帧率 20–30 fps。
- 状态切换 100 ms 交叉淡入；`SICK`/`HUNGRY` 不允许被普通动作打断。
- 动作与 `01-ai-agent.md` 的 `motion_sink` 共用；后续舵机只替换执行层。

## 5. 存档与持久化

### 5.1 G1 存档结构与提交规则

`growth_store.c` 明确编码小端字段，不直接序列化 C 结构体。NVS 命名空间 `pet_growth`，`snap0`/`snap1` 各 80 B，`active` 提交记录 16 B；与 02 旧存档及 nexus-core 的成长档案独立，不自动迁移或同步。

| 字节偏移 | 内容 |
| --- | --- |
| 0–15 | `PETG`、v1、长度、revision、CRC32（校验时 CRC 字段置零） |
| 16–23 | 最近成功的 64 位请求 ID |
| 24–63 | EXP、金币、保存时刻（Unix 秒）、每日周期、未互动秒数、亲密度、**有符号心情**、精力、饱食度、健康；各 32 位 |
| 64–69 | 喂食/玩耍冷却、今日摸头次数；各 16 位 |
| 70–73 | 连续低饱食/低精力秒数 |
| 74–79 | 等级、摸头冷却、最近动作、睡眠标志、2 B 保留零 |

- 写非活动槽 → 读回比对 → 写带 CRC 的 `active` → 读回确认；只有提交确认后才替换互动的 RAM 数值和发 `PET_EVT_GROWTH_CHANGED`。
- `active` 是提交依据，不能直接选 revision 更大的槽：较新槽可能是写入中断的候选。
- 驱动报错但读回确认已提交时按成功处理；确认仍为旧提交时返回 `STORAGE_ERROR`，可用原请求重试。无法确认提交结果时返回 `STORAGE_UNCERTAIN`、停止继续写入；重新初始化后用原请求 ID 重试，避免重复结算或旧 RAM 覆盖新提交。
- 活动槽损坏可回退较旧的有效存档，本次启动的快照 `save_recovered` 标明回退；可能丢失最后一次提交。后续写入保护实际恢复槽。两槽损坏、提交记录缺失或未知版本均保留原数据并停用成长服务，不自动重置或擦除 NVS；其他模块继续启动。
- 成功互动立即保存；普通衰减每 5 min 合并写。普通保存失败保留 RAM 的衰减结果，按周期或显式 `flush` 重试；失败互动不在 RAM 中预发奖励。
- 存储和互动在业务任务运行；快照读取不等待 Flash 锁，忙时返回 `NOT_READY`，显示层应保留上一快照。实际 Flash 耗时和磨损预算尚未实测。
- 工厂重置、导出/导入、旧版本迁移仍待后续切片；当前不提供删除存档的 UI 或命令。

### 5.2 时间与恢复

- 新档未对时时可用单调时钟本地互动；首次对时只建立时间锚，不重复结算已在线时间，也不清空已累积的每日次数。
- 已有真实保存时间的旧档在启动未对时时暂缓互动和结算，`time_ready=false`；对时后一次性结算 `min(max(now-saved, 0), 8 h)` 并持久保存，再开放互动。无时间来源时保持等待。
- 运行后按单调时间推进；墙钟回拨或向前跳跃不重复衰减、不刷新每日上限。长时间未调度也按恢复处理，单次最多八小时。
- 默认 UTC+8，`CONFIG_PET_GROWTH_UTC_OFFSET_MINUTES` 可配置固定偏移；每日摸头计数在本地 04:00 换日，周期编号只增不减；不处理夏令时。
- G1 的睡眠由 `sleep`/`wake` 显式切换；睡眠中喂食、摸头、玩耍均拒绝。22:00–07:00 只推导困倦状态，不自动改变睡眠模式。

### 5.3 服务端同步（二期）

2026-11-13 已实现只读快照上传和 CORE 展示，当前协议与验证见 [21](21-growth-sync.md)。实际主题为 `growth_status`，每 15 秒、非 retained，带 `deviceId`、随机 `bootId`、启动内递增 `reportSequence` 与存储状态；沿用 TLS/身份校验，不将历史草案中的 `checksum` 当作鉴权。

设备本地数值优先，CORE 展示设备档案，原有 CORE 专注档案继续独立结算，不回写覆盖。离线奖励/活动下发及跨端奖励去重仍为二期，首版不做。

## 7. 验收标准

### 功能

- 互动后 100 ms 内数值与 UI 更新；重复请求不重复结算。
- 升级曲线与表格一致；一次升多级正确；99 级封顶。
- 8 种状态按优先级展示，无卡死；状态切换 100 ms 内完成。
- 每日 04:00 重置任务与计数；跨时区/手动改时间不重复发奖。
- 离线 8 h 衰减符合公式；超过 8 h 不再累积。
- 掉电写入中重启：至少保留上一份有效存档；无 CRC 错误导致的无限重置。
- 导出/导入往返一致；未知版本拒绝覆盖。

### 资源与稳定性

- 存档写入 ≤50 ms；不阻塞 UI/音频。
- NVS 写入频率 ≤1 次/5 min（普通衰减）+ 重要事件；24 h 写入次数在预算内。
- 1000 次随机互动无溢出/NaN；数值始终在范围内。
- 30 天模拟衰减不出现负值/异常状态。

### 测试

- 主机：EXP、衰减、互动、状态机、CRC、迁移、幂等。
- 目标：NVS 双槽、掉电模拟、UI 动画。
- HIL：连续 7 天互动/断电/恢复。

## 9. G1 软件切片（2026-11-11）

已实现：喂食、摸头、玩耍、睡眠/唤醒、冷却与请求幂等、升级与数值范围、按秒衰减、每日摸头计数、状态推导、三秒升级兴奋、v1 双槽存档、启动恢复与运行任务。事件只报告已提交快照，普通 RAM 衰减可直接读快照。

未实现：成长屏幕与动画、状态切换滞回、AI 对话/专注奖励、每日任务/成就、环境联动、备份导入导出、服务端同步。前文这些内容仍是后续目标，不作为 G1 已完成能力。

### 桌面体验

在项目根目录执行：

```bash
./tools/simulate_growth.sh
```

依次输入 `feed`、`pet`、`play`、`sleep`、`wait 3600`、`wake`、`status`、`quit`。模拟器编译并运行固件同一套 engine/store/service，文件存储和 POSIX 锁替代 NVS/FreeRTOS；默认存档在忽略的 `firmware/build-growth-sim/state/`。重新执行沿用该档；可用 `--state-dir /tmp/pet-growth-demo` 隔离实验，父目录需存在。

`--epoch 1800000000` 可固定启动时间，下一次启动增加 Unix 秒数即可检查离线恢复；`wait` 分段推进在线时间，最多七天；`sync` 设置模拟墙钟，便于检查首次对时与回拨。退出前会 flush；此工具不会连接串口或烧录。

### 已验证与边界

- `tools/ci/test_host.sh`：纯引擎 30 天衰减、1000 次随机互动、升级封顶、每日 04:00/回拨、冷却/拒绝、状态优先级；真实服务的事务、重启、八小时上限、未对时、CRC 损坏、未知版本、提交错误和并发请求。
- 成长引擎与服务通过 AddressSanitizer/UndefinedBehaviorSanitizer；桌面文件存档在两个进程间恢复相同经验、金币、冷却和请求编号。
- ESP-IDF 的 NVS 分区生成器确认 64 KB 可静态容纳两份最大消息快照、最大长度凭据、温湿度存档、成长双槽及额外 80 B 写入候选；不代表运行中垃圾回收或磨损验证。
- ESP-IDF 构建结果记录在路线表；代码编译和主机边界测试不能替代真实 NVS 掉电、Flash 延迟/磨损、任务栈与 UI/音频并行验收。

## 10. G2 成长主页与单键互动（2026-11-11）

消息空闲页改为成长主页，显示等级、经验、金币、饱食、精力、心情、健康、亲密度，以及未读数、免打扰、待保存/对时/存档回退状态。

- 主页短按 BOOT 仍查看未读消息，长按至少 800 ms 后松开进入互动菜单。
- 菜单短按依次选择喂食、摸头、玩耍、睡觉、唤醒、返回；长按后松开执行。喂食显示 5 金币成本，玩耍显示 10 精力成本；前三项显示剩余冷却。
- 消息弹出取消菜单及当前成长手势；消息内短按仍确认已读。启动时按住、跨消息按下/松开、屏幕刷新失败时不能发起成长互动。
- 成长请求通过长度为 1 的队列交给独立工作任务；UI 等待结果期间禁止再次提交，显示保存中，随后显示真实业务结果。失败不会用成功提示掩盖。
- 同一 LVGL 任务拥有两个视图；未开启成长模块时保留原消息空闲页。当前 UI 仍依赖网络模块开关，关闭网络的配置保留 CLI 成长体验。

## 14. G6 温湿度成长联动（2026-11-11）

### 规则与生命周期

- 只使用当前启动的滤波后读数：`valid=true`、无错误码、质量 50–100、数值有限且温度 -10..60 °C、湿度 0..100%。读数年龄必须小于 30 s；未来、过期、乱序或重复时间戳不延长有效期。32 位采样毫秒回绕可用；长时间断流后允许新鲜读数恢复。
- 温度 <10 °C / >30 °C，或湿度 <30% / >80% 为不适；等于门槛不触发。温湿度同时不适只计算一份影响，表现先温度、后湿度。
- 按可确认的在线暴露累计，每小时额外扣 1 点 `mood`，内部沿用 1/3600 定点单位。无效/低质量读数立即清除影响，断流最多沿用至采样后的 30 s；子秒切换保留余量，不因高频更新丢失暴露。
- 不直接改变 `health`、奖励、任务、亲密或睡眠模式；原有心情影响健康恢复条件的规则仍保留。睡眠期间同样按有效暴露结算。重启后环境清空，不把最后一次环境外推到离线时段；已结算心情沿用原存档策略保存。
- 不增加持久化字段或版本迁移：仍写成长 v3 84 B。环境、有效期与暴露余量仅在 RAM，不因每次采样写 Flash；互动与每 5 分钟保存沿用既有事务及失败语义。

### 事件接入与表现

`svc_growth` 只依赖 `pet/climate.h` 契约，不调用 `svc_climate` 私有实现。启动时订阅 `PET_EVT_CLIMATE_READING`，验证事件来源和 payload 大小后只覆盖长度为 1 的最新读数队列。成长工作任务调用 `pet_growth_observe_climate()`，事件任务不承担成长 Flash 结算。任务等待资源/订阅全部成功的启动通知；启动失败时先停止尚未结算的任务，再释放队列和服务。关闭气候模块时不创建订阅/队列；UI 非阻塞读取快照，下一次轮询显示当前环境。

主页在原状态后显示“有点冷/热/干/湿”，原存档/对时警告优先。角色增加相应符号；发呆和开心可叠加抱臂/扇风/干燥动作与配色，其余业务状态保留主体表现，睡眠/生病不会被环境覆盖。菜单和消息遮挡继续停帧。HTML 预览现可切换八种状态及四种环境，各 42 帧。

### 桌面模拟

```text

status

```

`climate` 开始每 5 s 注入一次模拟滤波后读数；`climate-loss` 停止更新并等待过期，`climate-off` 立即发送失效读数。温湿度参数拒绝 NaN/Infinity/越界；连续输入代表新读数。模拟器仍复用真实成长服务，不能据此认定 DHT11 采样链路已实机通过。
